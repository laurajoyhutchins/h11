# Equal-budget selection comparison: architecture score vs source-size baseline

## Experimental outcome

Source: original h11 commit `62c5068c971579d61fa1b55373390e12f25fd856`, Git tree `5a1cacdb9d0d6e8d18e8161924ae18130da6c130`.

Protocol was [frozen](comparison_h11_preregistration.json) before the comparison. The successful, cache-safe run is [GitHub Actions 42562289253](https://github.com/laurajoyhutchins/h11/actions/runs/42562289253).

The architectural ranking and the deliberately simple baseline selected exactly the **same three modules**, though in a different order:

| Rank | Architecture ranking | Three largest directly test-imported modules |
| --- | --- | --- |
| 1 | `h11._state` | `h11._connection` |
| 2 | `h11._events` | `h11._events` |
| 3 | `h11._connection` | `h11._state` |

Both allocated three selection slots and three deterministic function-level `if` condition inversions per module. Both used the full original upstream h11 test suite. The selection scoring, candidate selection and mutation ordering were unchanged after the preregistration.

| Observation | Architectural | Size baseline |
| --- | ---: | ---: |
| Selected modules | 3 | 3 |
| Trial mutations | 9 | 9 |
| Detected by original tests | 5 | 5 |
| Invalid / inconclusive | 4 | 4 |
| Surviving valid mutations | 0 | 0 |
| Previously independent-verified codec modules selected | 0/2 | 0/2 |

**There is no observed selection advantage** for the architectural ranking at this budget. In this small reference case, its extra complexity reproduced the source-size baseline.

### Verification limits

The four invalid mutants caused collection errors rather than ordinary completed-suite test failures. They cannot be counted as cleanly killed or as surviving. Thus the valid-trial 5/5 detection rate is not a useful estimate of overall test adequacy.

A preexisting, **independently authored** chunked reader/writer contract bank was rerun, with 3/3 original contract probes passing and 6/6 hand-targeted semantic mutants detected. Neither ranking selected either independently oracle-covered implementation, `h11._readers` or `h11._writers`.

This bank gives a known positive control, **not** an equal independent behavioral oracle for each ranked candidate. Because the selected source modules are identical, an independently authored module-specific oracle would also evaluate identical source targets in both arms, so this pilot cannot identify a ranking advantage even if further oracles were written.

This is a calibration on the already-examined h11 codebase. It is not a blinded measurement of agent comprehension, architectural quality, or verification return on investment across repositories.

## Harness findings

The first attempted workflow failed because `research/selection/select.py` shadows the native CPython `select` module if imported by its bare module name while using subprocesses. The corrected comparison loads the research ranker from an explicit file location under a distinct module name and removes the conflicting directory from the import path.

The subsequent initial full run produced **inconsistent verdicts for identical source mutations across arms**, likely because Python cached bytecode while source was temporarily rewritten several times within a timestamp window. Its raw mutation scores should not be used.

The passing rerun explicitly purged `__pycache__`, disabled Python bytecode writes and fixed the hash seed. It also failed closed unless repeated mutants across arms had identical outcomes. That consistency check passed for all **nine unique source mutations**.

The original h11 worktree was verified clean after the trials and the final tree hash remained exact. There were no changes to `master` or the synthetic histories.

## Interpretation

Structural candidate discovery remains useful for identifying **possible** contracts and import closure boundaries. It does not follow that a weighted structural score is better at allocating independent verification effort. Here, the score was neither distinct from simple file size nor successful at recovering the previously demonstrated codec contracts.

The reasonable default is the **simpler, auditable baseline** until a separate, preregistered comparison on new repositories shows a meaningful advantage using coverage by independently justified, bounded behavioral oracles. If a ranking is retained, its complexity needs evidence, not just plausible weighting.
